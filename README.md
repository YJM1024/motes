# Motes Lite · 微粒

用对话把想法变成可以操作、保存和分享的网页应用。

**作者：杨俊敏**

[在线体验](https://motes-yangjunmin.yjm1024.chatgpt.site/) · [GitHub 源码](https://github.com/YJM1024/motes)

[![CI](https://github.com/YJM1024/motes/actions/workflows/checks.yml/badge.svg?branch=main)](https://github.com/YJM1024/motes/actions/workflows/checks.yml?query=branch%3Amain)

## 快速体验

1. 打开在线工作台，无需注册即可体验。
2. 选择或新建项目，描述应用需求，例如“做一个可以添加任务、标记完成并保存记录的任务清单”。
3. 工作台展示规划、执行、检查、保存四个阶段，在预览中直接操作生成的应用。
4. 继续用自然语言修改，查看源码和版本差异，或恢复历史代码版本。
5. 将选定版本发布为公开链接，或导出独立 HTML。

在线 Demo 使用游客公共空间，作品与通过 SDK 保存的业务数据由访客共享，适合直接体验和评审，请使用演示数据。

## 实现思路与关键取舍

工作台使用 React、TypeScript 和 Vinext，部署在 Cloudflare Workers，D1 保存项目、对话、代码版本和应用业务数据。真实模型先生成简短计划，再生成应用或修改补丁；工作台检查源码、编译 JSX 和 Tailwind 样式，最后保存完整代码版本并载入隔离预览。

| 设计选择 | 考虑与取舍 |
| --- | --- |
| 固定 React 19 + Tailwind CSS 4 工程 | 工作台维护入口与依赖，模型专注于 `src/App.jsx` 和 `src/index.css`，统一生成、编译、预览和导出路径；当前不安装任意依赖。 |
| 局部补丁与完整快照 | 修改位置须在原文件中唯一匹配且互不重叠，校验后统一提交；完整代码版本便于比较和恢复。 |
| 请求编号、内容指纹与事务保存 | 核对重复请求、约束并发修改，生成结果暂存后可仅重试保存，复用原模型结果。 |
| 游客公共空间 | 降低体验门槛，评审无需注册；当前以共享演示数据为范围。 |
| 代码与业务数据分开保存 | 代码版本可恢复，应用通过 SDK 显式保存的数据独立保留。 |
| 隔离预览与受控数据桥 | 应用在带 CSP 的 sandbox iframe 内运行，通过宿主 SDK 保存数据；模型密钥由服务端管理。 |
| 托管链接与 HTML 导出 | 托管页提供 SDK 数据桥，独立文件携带运行时和样式，可单独打开体验。 |

## 当前完成程度

| 能力 | 当前实现 |
| --- | --- |
| 真实模型生成 | 服务端调用模型完成简短规划与应用生成，界面展示四阶段进度。 |
| 连续修改 | 基于当前保存版本生成精确补丁，保留无关代码。 |
| 交互预览 | 生成应用在隔离 iframe 中运行，可直接操作表单、按钮和页面交互。 |
| 项目与应用 | 选择和创建项目，在项目内创建与切换应用。 |
| 工作台持久化 | D1 保存项目、需求、对话、完整代码版本和请求状态。 |
| 应用业务数据 | 提供 Motes SDK，显式保存任务、预算等共享 JSON 数据。 |
| 版本管理 | 历史预览、七文件源码查看、实际增删行比较、代码版本恢复。 |
| 发布与导出 | 发布选定版本的公开链接，或导出独立 HTML。 |
| 请求恢复 | 刷新后核对原请求结果，支持暂存生成结果的保存重试。 |
| 移动界面 | 小屏下可在聊天和预览间切换。 |

已有单文件 HTML 应用保留原有流程。示例模式提供旅行预算、任务看板、番茄钟及有限修改，不调用模型；真实模型模式单独标注。

**当前范围：** 聚焦固定依赖的小型前端应用。源码面板为只读；暂未实现个人账号、代码流式输出、任意依赖安装、通用多文件工程和 ZIP 工程包。代码恢复只切换代码版本；普通输入需由应用显式通过 SDK 保存。独立导出的 HTML 不连接宿主数据桥，SDK 数据作为临时状态使用。

## 本地运行

推荐 Node.js 24 与 npm。首次克隆后，在仓库根目录依次运行：

```sh
npm ci
node -e "const fs=require('node:fs'); if (!fs.existsSync('.dev.vars')) fs.copyFileSync('.dev.vars.example','.dev.vars',fs.constants.COPYFILE_EXCL)"
npm run build
npm run db:init:local
npm run dev
```

默认开发地址为 `http://127.0.0.1:5173/`，以终端输出为准。示例配置可直接运行本地示例；真实模型模式在本地 `.dev.vars` 中配置 `OPENAI_API_KEY` 与 `OPENAI_MODEL`，可选用 `OPENAI_MODELS` 设置模型白名单。示例中 `MOTES_WORKSPACE_VISIBILITY=shared` 表示游客公共空间。`.dev.vars` 已被 Git 忽略。

`db:init:local` 只初始化全新的本地 D1，使用 `.wrangler/state`，不连接生产库。已有库先备份该目录、核对迁移状态，再仅应用尚未执行的 SQL 迁移。

## 工程检查

```sh
npm test
npm run typecheck
npm run build
npm run verify:http
```

CI 在 Ubuntu 与 Windows 上运行测试、类型检查、构建、全新本地 D1 初始化和 HTTP 检查。HTTP 检查在构建和本地数据库初始化后执行，使用示例模式，不调用模型。

## 后续扩展与优先级

1. **P0：生成应用的实际使用体验。** 完善空数据初始化、异步保存反馈、连续修改和恢复后的数据兼容，优先保证常用应用流程。
2. **P1：错误定位与恢复。** 提供更具体的源码位置、补丁冲突与数据冲突指引，改善请求核对和保存重试体验。
3. **P2：工程能力扩展。** 根据实际需求支持受控多文件工程与独立工程导出，再评估个人空间和更丰富的运行环境。
