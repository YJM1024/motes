# 架构设计

## 工作台与生成应用

工作台使用 React、TypeScript 与 Vinext，服务部署在 Cloudflare Workers，数据保存在 D1。宿主工作台管理创作流程，生成应用在受限 iframe 内运行。

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 工作台入口 | `app/page.tsx`、`app/lite/` | 项目导航、对话、预览、源码、版本和发布。 |
| API | `app/api/` | 会话、项目、生成、恢复、发布与 SDK 数据接口。 |
| 生成服务 | `lib/forma/server.ts`、`lib/forma/model.ts` | 模型计划与执行、请求状态、版本提交。 |
| 应用工程 | `lib/motes/react-project.ts`、`react-patch.ts`、`react-render.ts` | 固定工程、精确补丁、JSX 与 Tailwind 编译。 |
| 数据一致性 | `lib/motes/results.ts`、`runtime-data.ts` | 结果暂存、事务保存、业务数据和 revision 校验。 |
| 数据结构 | `db/`、`drizzle/` | 数据表与迁移。 |

`forma` 保留已有数据和模块命名。部分服务模块沿用已有能力，当前默认产品入口为 Lite 工作台。

## 一次生成如何完成

1. 客户端记录请求编号、需求、目标应用与当前代码版本。
2. 服务端校验来源、空间归属、容量与处理锁，登记请求和用量。
3. 模型先生成简短计划，再返回应用工程或精确修改补丁。
4. 服务端校验输出，编译 JSX 和静态 Tailwind；构建阶段不执行生成的 App。
5. 暂存结果，通过 D1 批量事务写入版本、当前代码指针和请求回执。
6. 客户端载入新版本预览，用户操作应用并继续提出修改。

## 版本与请求一致性

请求编号与内容指纹用于核对原请求，应用锁与当前版本校验约束并发修改。结果暂存后可单独重试保存，成功提交的版本与请求回执保持一致。

刷新后客户端依据原请求记录查询结果。停止本页等待仅中止客户端等待，后续以服务端记录核对执行结果。

代码保存完整快照。局部修改要求补丁在原文件中唯一匹配且互不重叠，版本恢复只改变当前代码指针。

## 预览与应用数据

生成页面在 `sandbox="allow-scripts allow-forms"` iframe 内执行，不授予同源权限。CSP 限制外部资源、网络、嵌套页面和表单跳转。React 编译使用固定依赖，运行时与样式内嵌。

应用通过 `window.motes.data` 与宿主通信。宿主核对 iframe 来源、独立通道和消息格式，服务端核对应用、可用版本和 revision。

代码与业务数据独立保存。托管发布页提供数据桥；独立 HTML 导出的 SDK 数据作为临时状态使用。

## 体验与资源控制

游客公共空间便于直接体验，作品与显式保存的业务数据由访客共享。匿名浏览器会话用于请求记录与用量控制，模型密钥保存在服务端。请求长度、输出大小、处理时限、版本容量与生成额度由服务端约束。
