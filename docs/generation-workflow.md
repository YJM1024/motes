# Motes Lite 生成工作流

Lite 的生成请求通过四个阶段展示进度：**规划 → 执行 → 检查 → 保存**。进度只说明当前阶段，不会展示隐藏推理或生成中的代码流。新应用默认是 React 19 + Tailwind CSS 4 固定工程；已有 HTML 应用继续走原有 HTML 路径。

## 四个阶段

1. **规划**：模型模式会先生成简短任务清单，作为后续执行的参考。demo 模式使用本地预设计划与模板，不会伪装成 AI 规划，也不会调用模型。
2. **执行**：新建 React 应用时只生成 `src/App.jsx` 与 `src/index.css`，固定入口、package 和 Vite scaffold 由工作台提供。修改 React 应用时，模型返回严格格式的局部文件补丁，只能精确修改这两个源码文件；每个搜索片段须在原文件中唯一匹配，补丁不可重叠并受大小限制。已有 HTML 应用仍使用原来的完整 HTML 创建与 HTML 补丁修改路径。
3. **检查**：所有候选结果都经过 HTML 结构检查。React 工程还会解析 JSX 和模块导入，并从源码中的 Tailwind 类编译 CSS；模块只允许导入 React，CSS 不允许外部导入或 URL。React 源码按静态、完整的 Tailwind 类名编写。编译不执行生成的 App，也不等于功能完全正确或通过浏览器功能测试；旧 HTML 的结构检查本身也不表示其脚本经过执行测试。
4. **保存**：检查通过后才创建并保存新版本。任何规划、执行或检查失败都会保留原保存版本，不会将失败结果写成版本。

模型模式通常需要两次上游模型调用：一次生成简短计划，一次执行生成或修改；两个阶段的 token 用量汇总记录，额度仍按用户请求计数。demo 模式在本地选择预设计划和模板，不进行模型调用。页面显示阶段状态，不提供代码流式输出。

## 版本对比与业务数据

预览区工具栏中的“版本对比”可比较两个已保存版本，查看逐行新增、删除与未变代码。超出受限对比预算时会明确提示无法展示，不会以估算内容代替实际差异。

版本还原和版本对比针对保存的应用版本。React 版本对比可选择工程中的源码文件查看差异；旧 HTML 版本仍比较 HTML 文本。应用经 Motes SDK 明确写入的业务数据保存在独立数据层，不会随代码版本还原而回滚。

## React 预览与独立导出

固定 scaffold 提供真实 React 19 与 Tailwind CSS 4 工程，采用独立 Vite 7.3.7 工具链。源码面板可查看 7 个完整工程文件，其中只有 `src/App.jsx` 和 `src/index.css` 可由后续生成修改。固定工程不接受任意 npm 依赖、容器、任意多文件或 ZIP 工程包。

预览、公开页面、分享和 HTML 导出将 React 源码编译成内嵌的 runtime 与 Tailwind CSS，不加载 CDN，也不使用 `eval` 执行生成源码。工作台预览和公开页面中的 SDK 桥连接 Motes 共享数据；独立 HTML 没有宿主 SDK 桥，会标明数据只在当前临时使用，不会假称已保存。旧 HTML 导出保持原内容，不改变既有 HTML 应用行为。

独立 scaffold 已在单独导出目录按其 `package.json` 正常安装并执行生产构建；过程和产物路径记录在[构建验证文件](../../../output/motes/react/scaffold-build-check.json)及同目录日志中。此验证说明工程可安装和编译，不是浏览器中的完整功能验收。

## Lite 范围

Lite 不提供代码流式输出、登录流程或 ZIP 打包导出，也不支持任意 npm 依赖、容器或任意多文件工程。固定 React scaffold 可导出成单文件 HTML；旧 HTML 应用沿用其原有单文件方式。界面能力及服务端配置仍以当前部署为准。
