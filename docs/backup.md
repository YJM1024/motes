# JSON 备份与私有副本导入

管理页“备份与导入”提供单应用或项目内多应用的 JSON 文件。HTML 导出仍用于独立运行；JSON 备份用于恢复完整代码历史，不包含预览中的临时业务输入。

## 范围与限制

备份包括项目/应用名称与简介、应用收藏/归档、标签、完整版本代码/需求/摘要/来源/时间、当前版本编号、版本名称及重要标记，以及项目和应用当前有效的安全设置偏好。设置导入为快照覆盖，后续移动应用不会自动切换这些已恢复偏好；用户仍可在设置中重置为继承。模型是否可用由当前服务端决定。

不读取或输出服务端身份、Cookie、模型密钥、请求与额度日志、分享记录或分享 token。原应用/版本/标签数据库 ID 不进入文件；文件内使用局部标签键和版本编号。备份含用户需求与全部代码，应妥善保存；它不是加密文件，也无法替用户清除自己写在代码或需求中的秘密。

每份最多 2 MiB、10 个应用、合计 200 个版本，每应用 60 个版本。导出先通过 SQL 聚合检查数量及 HTML/需求/摘要 BLOB 字节，并留出元数据预算，超限不会先加载全部代码；最终编码后再次检查大小。导入在解析前流式累计请求总字节，超过 2 MiB 即拒绝。超限请单应用或按项目分批导出。

## 确认与恢复

选择文件后先在浏览器本地检查，再由服务器独立校验，展示项目名、各应用名与应用/版本数量。预检不写入作品，也不运行代码。用户勾选确认后才导入；服务器用预检内容哈希绑定确认的文档，文件变化需重新预检。

每次导入新建一个名称带“导入”的私有项目。应用与版本全部使用新 ID，历史原文与当前指针按版本编号映射恢复；不覆盖原作，也不创建或恢复任何公开分享。归档应用仍保持归档，可在管理页归档列表中恢复。已有同名标签复用当前标签与颜色，其余标签新建。身份、目标引用和数量限制由服务端独立检查，容量在原子写入事务中再次校验。

项目、应用、版本、注释、标签关联、设置与导入收据使用一个 D1 原子批处理。写入失败不留下导入半成品，已有作品不变。每次确认有独立请求编号；网络异常重试复用原编号，已完成则取回同一批结果，移动应用后也不会再次导入。重新选择文件会建立新的导入操作。

## 接口与数据兼容

- `GET /api/backup?appId=…` 或 `?projectId=…`：只读导出，响应 `motes-backup` 格式版本 1。
- `POST /api/backup`，`{action:"preview",backup}`：返回 `previewHash`、项目名、应用名及数量/字节数。
- `POST /api/backup`，`{action:"import",requestId,previewHash,backup}`：确认导入；返回 `{projectId,appIds,imported:true}`，首次 201、同请求重试 200。

POST 必须匹配本站 Origin 且拥有现有匿名会话。服务器拒绝未知字段、秘密或分享字段、损坏 HTML、重复版本、错误当前指针与文件内无效标签引用。导入文件无法指定服务器 owner、现存数据库对象 ID 或分享 token。代码后续仍只在工作台受限 iframe 中运行。

本批无需新表或迁移。幂等收据复用 `forma_requests`，使用独立 `mode="backup-import"`；该模式的 `project_id` 为新管理项目 ID，`result_version_id` 为最多十个新应用 ID 的 JSON 收据，只由备份处理器解释。不计入 `demo`/`model` 生成额度，不导出请求表。恢复注释依赖前置 `0004_version_annotations.sql`；不改动分享的 `0003` 表。

## 验证

`node --test tests/backup.test.mjs` 使用真实 SQLite、外键、事务和生产查询，覆盖完整导出、新 ID/指针/注释/设置恢复、访客隔离、分享排除、损坏和超大输入、写入失败回滚、容量竞争与并发幂等。测试需要前置 0000–0004 迁移文件，不调用模型。浏览器流程与部署状态由整合后的验收另行记录。
