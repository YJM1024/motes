# 可选模型与真实用量

本页说明模型偏好与真实用量。两组方案比较、运行诊断辅助修复和讨论的交互分别见对应功能文档；不提供账户余额或精确费用。模型连接只由服务端管理。

## 模型配置与选择

服务端 `OPENAI_MODEL` 为默认模型，新增可选 `OPENAI_MODELS` 逗号白名单，最多八个 ID；留空兼容旧配置，只启用 `OPENAI_MODEL`。没有 Key 时返回空模型列表，继续诚实使用示例模式。浏览器不能传入白名单之外的模型，也不能通过设置改变密钥、超时、输出上限和每日额度。管理员应先核对账户实际可访问的 ID，再配置并发布；列表访问并不代替真实生成验收。

2026-10-30 使用已获授权的现有连接，只读 `GET /v1/models` 返回 200，确认 `gpt-6-luna` 与 `gpt-5.4-mini` 均列出。本批没有真实生成。建议保持已通过核心流程的 `gpt-6-luna` 默认；`gpt-5.4-mini` 可作为用户主动选择的另一个代码生成候选。

官方说明 [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) 面向高效、高频任务，支持 Responses 与 `low` 推理。标准输入/输出分别为每百万 Token $0.10/$0.50。[GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) 明确支持代码任务、Responses 与 `low` 推理，标准输入/输出分别为 $0.75/$4.50；它比 Luna 更贵，不能称作更便宜的替代。以上为核对时的公开标准价，实际适用价格与账单另行确认，界面不据此展示估算费用。

`GET /api/session` 保留原字段并增加 `models`、用于草稿隔离的 `workspaceId`。`GET/POST /api/settings` 的偏好增加可选 `model`，沿用工作空间 → 项目 → 应用的继承方式；`null` 重置为继承。白名单中移除原偏好后，有效值回退当前默认模型，来源标为 `server`，不把旧偏好继续伪装为可用选项。设置页面展示模型及有效来源，下一次 AI 生成真正采用该设置。

`POST /api/generate` 可选显式 `model`，只能来自白名单；优先于已保存偏好。未显式带新字段时，旧请求指纹完全保持。显式带模型时才追加带名的模型对象进入指纹，避免与项目目标字段混淆。已完成请求始终先核对原记录，重试不再次生成；设置或白名单后续变化不影响已完成结果取回。

JSON 备份兼容旧文件缺少 `settings.model`，新文件可保存有效模型偏好；导入不能带入 Key 或扩大当前白名单，禁用模型会在设置读取时安全回退。

## 用量与记录覆盖

`GET /api/usage` 仅当前匿名访客，响应不缓存，不接受切换 owner。返回今日 UTC 的 AI/示例请求已用、剩余与上限，AI 成功/失败/待完成数，实际已知 Token 小计与覆盖数，以及最近五十条模型任务的模型、状态、时间和耗时。

新 `0006_model_usage.sql` 仅创建用量表与索引，不回填旧任务。记录请求模型与 API 回执模型、耗时、HTTP 状态、输入/输出/总 Token 和固定错误分类；不保存需求、代码、Key 或原始错误消息。数据来自 Responses 的真实 `usage.input_tokens`、`output_tokens`、`total_tokens`。输出包含推理和其他不可见内容，不能按可见代码长度估算。[官方 Token 计数说明](https://developers.openai.com/api/docs/guides/token-counting)、[Responses 字段定义](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)。

网络中断、超时或缺少 usage 时为 `null`/未知；只有 API 明确返回零才显示零。部分字段缺失时仍保留已知小计，覆盖为 partial。旧请求没有补算 Token，界面以“完整回执条数 / 今日尝试数”标出缺口，不将缺失计作零。Worker 意外终止而没有完成记录的任务显示结果待核对。

额度仍以现有请求登记为权威：每访客每日 AI 10 次、示例 100 次，全站 AI 50 次、示例 2000 次，按 UTC。进入生成流程后失败也占次数；参数验证失败或容量未获准不算一次已接受生成。同一次幂等重试不重复计数。manual、fork、backup-import 和示例任务不写入模型 Token 记录。个人剩余额度不是全站剩余额度，也不是 OpenAI 账户余额。

新模型任务在同一事务中登记预算和运行中用量；成功保存与成功用量在同一提交中更新。输出校验或保存失败仍保留已获得的实际用量；保存后读取失败不会把成功记录改为失败。`budgetReservation`、`usageReservation` 和 `usageCompletion` 供构建、修复、候选与讨论共用；讨论每次占一次 AI 额度，两组候选预留两次，同一幂等请求不重复计费登记。

## 验证与部署前置

本批使用真实 SQLite 与模型 fetch mock，覆盖模型偏好继承、请求选择与实际 API 参数、未知模型拒绝、无 Key、停用回退、旧幂等指纹、失败/未知/部分/显式零用量、隔离、额度与保存后读取异常。没有启动新预览或执行真实生成；模型读取只进行了无生成费的列表核对。

先应用前置模板 `0005` 和新 `0006` 的 schema-only 迁移，再发布代码。实际配置白名单由部署者通过受保护的服务端配置工具完成，源码及示例变量文件不含真实值。部署后需要另外完成可用模型切换与真实回执验收。
