# 运行诊断与主动修复

工作台只对当前隔离预览的副本注入 `error` 和 `unhandledrejection` 监听。持久 HTML、历史版本、导出文件、分享页和源码编辑器草稿不包含诊断桥；诊断不写入数据库或服务器日志，不增加数据表。

为避免把用户输入、密钥或业务数据带出预览，桥只传递固定白名单错误类别和数字行列，不读取错误 message/stack、DOM 输入、控制台内容或拒绝原因原文。预览包装会影响行列位置，诊断属于排查提示，不保证与保存源码逐字对应。

每次切换版本或刷新预览分配安全随机通道。父窗口必须同时匹配当前 iframe 的 contentWindow、opaque origin `null`、协议、通道和严格字段 schema；其他窗口、旧 iframe、过期通道及多余字段均忽略。桥和父窗口分别限制每 1.5 秒 3 条、每次预览最多 10 条；父端合并重复类别/位置。通道只限定预览会话，不是对不可信应用代码的认证，当前 iframe 自身仍可伪造受限提示。

只有收到合格运行诊断才显示面板。用户可展开类别和位置、收起面板，或进入源码手动修复。没有模型配置时明确说明无法 AI 修复；历史预览须回到当前版本或建立副本后再准备模型修复，避免将历史错误应用到错误的当前代码。

“准备 AI 修复需求”只构造可编辑需求，不调用生成接口。有未发送需求时必须明确替换或追加，取消保留原稿，追加遵守 4000 字上限。准备后模式明确为 AI，所选实际模型显示在工作台；用户点击发送才会走既有的单次生成和用量记录。不会自动重试、循环修复或以错误消失冒充已修好，仍应实际操作验证结果。

诊断预览继续使用 CSP、opaque `sandbox="allow-scripts allow-forms"` 和宿主 `frame-src 'self'`，不增加同源、网络或其他预览能力。

## 验证

`node --test tests/runtime-diagnostics.test.mjs` 测试纯事件来源、协议/通道/schema、隐私字段拒绝、位置范围、重复合并、双重限流与总量上限，并在 VM 中执行实际注入脚本验证错误原文和任意拒绝值不会上报。修复请求测试验证截断为最多五条安全诊断，保留安全和功能要求，不触发网络调用。

浏览器验收需在已保存的测试应用中制造普通错误及 Promise 拒绝，确认工作台按事实提示，导出源码不包含桥；检查其他窗口消息被忽略、刷新后旧诊断清空、有草稿时追加/替换/取消、无模型说明及源码手修入口。此批不包含自动模型调用或错误修复成功保证。

源码编辑器和模板编辑的放弃确认已统一为站内“继续编辑/明确放弃”，Esc 先取消确认；浏览器离开页面的未保存保护仍保留。
