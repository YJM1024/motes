# 请求核对与刷新恢复

本批没有增加后台任务队列。浏览器等待、刷新或状态查询，都不会使 Cloudflare Worker 在后台持续执行。状态来自已有请求记录和该请求自己的有效处理租约；Worker 仍可能中断或超期。

## 只读状态接口

`GET /api/requests/:id` 依赖当前匿名访客 Cookie，查询原生成请求。跨访客、无记录或无效编号使用相同 404 语义；不接受浏览器提交所有者，不改变请求、锁或结果。仅处理应用生成的 `demo`/`model` 请求，排除讨论线程、候选方案 namespace 及导入/复制回执。

| 状态 | 含义与行为 |
| --- | --- |
| `done` | 返回原请求精确持久版本的 `result`，及 `projectId`、`resultVersionId`；不把之后生成或还原的当前版本冒充这次结果 |
| `running` | 原请求仍有匹配应用 ID、请求 ID 且未超期的租约；只说明仍在有效处理时限内，不保证 Worker 正在执行 |
| `failed` | 已记录失败，可明确重新发送 |
| `expired` | 没有原请求自己的有效租约，可重新发送 |
| `not-found` | HTTP 404；客户端重试保留原编号，不能假定请求从未到达 |

`done.result` 仅包含 `projectId/title/versionId/number/html/createdAt`。接口不返回 fingerprint、需求 prompt、对话历史、访客资料、Key 或模型配置。工作台确认 `done` 后使用已有所有者接口读取完整应用，恢复版本列表并去除对应遗留失败消息。

## 客户端恢复

发送前同步保存 outbox 中的原请求编号、原需求与目标上下文。刷新时最多恢复最近 20 条经过校验的记录，去重并丢弃本地携带的未核实重试授权。应用 ID、新建目标项目和新建草稿 context ID 分开匹配；切换应用或明确新建后，旧结果不能自动抢占当前界面。

只有恢复中的 outbox 项会被查询，正在等待响应的生成 POST 不同时轮询。每项最多自动查询 20 次，退避为 2、3、5、8、12 秒，之后最多每 15 秒一次；最多两个状态/结果读取序列并发，单次状态或项目读取有 15 秒客户端超时。断网、暂时错误或结果读取失败只继续核对原请求，达到上限后暂停并提供再次检查。401/403 等需要用户处理的响应立即暂停。

确认 `failed`/`expired` 才为重发分配新编号；404 沿用原编号。当前 POST 明确返回已拒绝或已失败的响应时也可重试，但刷新后仍重新核对原编号，不信任持久化的授权标记。重试保留原需求、模式、应用、目标项目和基础版本，不吞掉用户正在编辑的下一条草稿。

取消等待、离开上下文、开始新操作或重试会使旧查询的代次失效，并通过 AbortSignal 停止客户端状态/结果读取。旧 POST 成功或失败回调也按请求编号核对，不能删除或覆盖同一消息的新重试。已经开始的服务端模型调用或费用不因此保证取消。已保存的较新版本不会被迟到的旧读取覆盖。

## 验证边界

真实 SQLite 测试覆盖最小返回数据、所有权、每种状态、精确租约匹配和只读性；纯状态/轮询测试覆盖退避上限、断网、401 暂停、404 同编号、确认失败新编号、上下文/代次隔离、迟到的状态与项目读取、POST 回调、草稿保护。本批不调用真实模型、不部署、不承诺持久队列。父任务合并后需用浏览器补验刷新恢复、切换上下文和草稿保留。
