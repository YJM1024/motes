# 源码草稿与版本资料

在工作台打开“源码与版本”，选择要编辑的已保存版本，再点击“编辑所选源码”。编辑器将源码加载为本次会话草稿；初始预览仍展示应用当前版本，修改文字不会自动运行或保存。

- **运行草稿**：只更新编辑器内的隔离 iframe，页面明确标记草稿；之后继续修改时，已运行预览保持原样，直到再次运行。
- **恢复已保存代码**：确认后将草稿恢复到所选版本，预览回到应用当前版本。
- **保存为新版本**：完整 HTML 经过验证后新增 `manual` 手工版本并设为当前，保留所有旧版本；不调用模型、不占模型调用额度。
- **版本资料**：展开子面板编辑所选已保存版本的名称及重要标记。该操作只改变注释，不改变 HTML、版本数量或当前指针。

草稿存在编辑器内存中；关闭、切换基础版本或离开前提醒未保存修改。保存失败保留草稿，网络重试沿用同一请求编号核对已有结果。当前尚无跨设备草稿或自动保存草稿能力。

## 保存接口

`POST /api/projects/:id/source`

```json
{
  "baseVersionId": "所选已保存版本ID",
  "expectedCurrentVersionId": "打开编辑器时的当前版本ID",
  "html": "完整单文件 HTML",
  "requestId": "UUID",
  "name": "可选的新版本名称"
}
```

基础版本可以是历史版本，但必须属于当前访客的此应用。保存时当前指针必须仍匹配 `expectedCurrentVersionId`；期间发生生成、还原或其他保存时返回 409，不覆盖新成果。HTML 至少 100 字符、最多 180000 字符，须具有完整 doctype/html/head/body；整个 JSON 请求最多 1200000 字节。结构检查不证明 JavaScript 逻辑正确。

保存使用 D1 原子事务，事务内复验归属、基础版本、当前指针、生成锁和 60 版容量；新增编号按数据库内最新版本递增。请求编号与内容指纹登记到共用请求表，`mode=manual`，成功重试不重复创建版本。来源或内容不同的同编号请求返回 409。失败事务不留下版本、注释、请求收据或新锁。

## 版本资料接口

`POST /api/projects/:id/versions/:versionId` 接受 `name`（最多 80 字，可清空）及 `important`（布尔值）。两个字段分别更新，未提供字段保留；不接受 HTML 或当前指针字段。服务端通过版本和应用归属联合检查，仅写入 `motes_version_annotations`。

版本 DTO 的 `mode` 新增 `manual`，并返回 `name`、`important`；手工版本没有模型 ID。工作台明确显示“手工编辑”，之后继续生成仍从有效设置选择 demo/model，不将 manual 作为生成模式。历史副本允许保留 manual 来源。

## 隔离与验证

草稿预览复用工作台的 CSP 包装与 `sandbox="allow-scripts"`，不授予同源、表单提交、弹窗或顶层导航权限；原始 HTML 不作为工作台 DOM 执行。安全策略不写回源文件或导出内容；导出后独立运行不具有工作台的 iframe 隔离边界。

追加 schema-only `0004_version_annotations.sql` 与对应 Drizzle 元数据，接在分享功能的 0003 后。旧迁移不变，不回填或重写任何历史代码。

真实 SQLite 测试覆盖手工保存、幂等、非法输入、来源/访客/版本边界、历史基础、并发容量、生成锁、事务回滚、保存前状态变化及只更新资料。模型续改测试使用模拟响应，验证手工基础代码进入原生成链路，不发起真实模型调用。浏览器端需另验草稿运行、关闭提醒、手机版布局、资料保存和手工版本标记。
