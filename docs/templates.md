# 个人需求模板

创作输入框旁的“模板”打开按需模板库。个人模板保存在当前匿名工作空间，支持创建、名称/需求编辑、删除、名称与内容搜索，以及“保存当前需求”。内置三个灵感起点明确标记只读，不计作个人保存；可另存为个人模板后编辑。

选择模板只填入需求，不发送、不创建应用、不调用模型。当前已有需求时，必须明确选择“替换当前需求”或“追加到末尾”；取消保持原稿。追加超过 4000 字时不可操作。首页三个灵感卡也采用先填入、再由用户编辑发送的流程。

个人模板名称为 1–80 字、需求为 1–4000 字，每个工作空间最多 50 个。空白草稿不能保存；超长草稿先精简。删除模板不删除应用、版本或已经填入的需求。模板编辑取消或关闭时提示尚未保存的修改；输入失败后保留，网络重试沿用相同请求编号。

## API 与持久化

- `GET /api/templates?q=`：返回个人 `templates`、明确只读的 `builtins`、个人总数 `total` 及 `limits`。搜索最多 100 字，只过滤显示结果，总数仍是此空间的完整数量。
- `POST /api/templates`：`action` 为 create / update / delete，所有操作必须携带 UUID `requestId`。创建提供 `name`、`prompt`；更新提供 `id` 及至少一个待改字段；删除仅提供 `id`。
- 返回最新完整模板库。创建首次成功为 201，更新、删除和已完成重试为 200。字段/长度无效为 400，来源无效为 403，不属于当前访客或已不存在为 404，请求编号冲突为 409，个人数量达到上限为 429。

服务端从 HttpOnly Cookie 解析身份，自动找到该访客工作空间，不接受客户端指定所有者或空间。每次查询和写入都验证空间归属；内置灵感不在个人模板表中，没有编辑/删除接口。

追加 schema-only `0005_personal_prompt_templates.sql` 和 Drizzle 快照，接在稳定的 0004 注释表之后；不修改旧迁移或已有应用。个人模板存入 `motes_prompt_templates`。写入和请求收据位于同一 D1 事务，容量在插入 SQL 内复验；失败整体回滚。

收据复用 `forma_requests`，使用 template-create / template-update / template-delete 模式，均不计入模型额度。请求编号按访客、动作及内容指纹核对。重复创建不增加记录，重放旧更新不覆盖后续结果，重放已完成创建或更新不会恢复后来被删除的模板。

## 验证与边界

```sh
node --test tests/templates.test.mjs
```

真实 SQLite 覆盖 CRUD 与搜索、访客隔离、只读内置边界、字段与长度验证、Origin、幂等/并发最后一个名额、写入失败回滚、提交后响应失败恢复，以及明确追加/替换和长度边界。模板测试禁止模型网络调用；模板不改写应用或版本。

浏览器需另验模板库的手机布局、Esc/取消、当前需求另存、已有草稿替换/追加及首页灵感先填入。当前没有模板市场、共享模板、正式账号或跨设备找回；清除 Cookie 后无法恢复原匿名空间。
