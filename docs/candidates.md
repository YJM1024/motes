# 多方案生成、比较与采用

当前支持 2/3/4 路方案，使用同一所选模型和不同生成策略；用户查看结果后自行比较、重试失败单路或采用，不自动评分或自动择优。独立比较页 `/compare` 当前可用。主创作界面内联发送、进度、重试、比较与采用仍在开发，尚未上线，不计入 v18 已交付范围。

## 生成、预算与恢复

AI 方案由用户选择数量并明确确认对应调用数。服务端只接受 2、3、4；模型必须来自服务端白名单。创建请求可带 `count: 2|3|4` 与 `confirmCalls: 2|3|4`，两者必须一致。兼容旧请求时可省略 `count` 并使用 `confirmTwoCalls: true`，其含义固定为两路。示例模式不调用模型。线上当前 `MOTES_REQUEST_LIMITS_ENABLED=false`，关闭访客/公共空间/全站每日次数限额；真实用量、请求幂等、并发锁、CAS/版本校验以及模型服务方余额、限流和超时仍然生效。

创建后各候选独立保存 HTML、状态、策略和错误分类。每路失败可在用户确认后单独重试；重试一次对应一次新尝试/调用。刷新或连接中断时按原请求编号读取状态，避免重复生成。采用已有应用前会检查基准版本、生成锁和容量；采用到新应用也会校验目标项目与容量。采用只保存已生成结果，不再次调用模型。候选未采用前不会改变原应用当前版本。共享空间中的项目、应用、对话和已保存数据对所有访客公开且可修改，不存在私有应用隔离。

## API 概要

- `GET /api/candidates`：读取当前共享空间最近的方案组元数据。
- `GET /api/candidates/:id`：读取方案组和候选详情。
- `POST /api/candidates`：创建方案组。核心字段为 `{requestId,prompt,mode,model?,appId?,baseVersionId?,managedProjectId?,count,confirmCalls}`；`count` 与 `confirmCalls` 仅取 `2|3|4` 且须相同。旧的两路载荷可用 `confirmTwoCalls:true`。
- `POST /api/candidates/:id/retry`：按候选 ID 和前次尝试 ID，携带新 `requestId` 与 `confirmOneCall:true`，恢复或启动单路重试。
- `POST /api/candidates/:id/adopt`：载荷 `{candidateId,asNew?}`；将已保存结果采用到原应用或新应用，不产生模型调用。

写操作校验本站 Origin、请求身份及当前空间/目标有效性。候选比较和单路重试均保留既有成果，遇到未确认状态时先核对原请求。

## 验证边界

自动测试覆盖真实 SQLite 与模拟模型下的预算/并发/幂等、失败恢复、保存、采用、冲突和权限路径；发布时测试环境每日次数限制关闭不影响这些逻辑验证。v18 UI 验收覆盖桌面及 390px 布局和线上管理页状态，不等于三/四路真实模型质量评估。历史双路真实模型记录仍是历史证据，不外推为本轮测试。`tests/candidates-smoke.mjs` 仍有旧的两路假设，待更新；它不是 v18 已执行的验证证据。
