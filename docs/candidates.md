# 两方案生成、比较与采用

当前生产支持用户选择 2/3/4 组，最多 4 组；v8 起已包含此能力。默认工作台仍为单次生成。管理页“高级 · 多方案比较”进入独立 `/compare`，不会自动生成。候选分别保存，明确采用才应用结果。

## 成本与预算

AI 模式必须明确勾选确认两次模型调用，再点击生成。两方案使用同一个白名单模型、两种固定布局策略，均保留用户明确功能和约束。新应用可选择目标项目，也可基于已有应用当前版本生成候选；项目/应用有效偏好继续生效。

两次调用使用与单次生成相同的每日访客/全站预算与真实 usage 记录。第一条子请求在事务中检查至少有两份额度；第二条依赖第一条成功登记。组、两个子请求、生成锁和用量记录在同一事务准备完成后，才并行发起两个请求。剩余访客或全站额度不足两次时，零模型调用、零子请求登记，提示返回单次生成。失败也占已接受的次数，单纯读取/重试原组与采用不会再次调用模型。

没有 Key 时只能显式使用示例模式，提供蓝色与绿色两种预设主题，页面明确标注 0 次模型调用；支持范围沿用预算、看板、番茄钟示例，不把它们说成 AI。两次示例仍占两份示例额度。

## 独立结果与恢复

每个候选独立保存 HTML、状态、策略及固定错误分类，并关联自己的预算与真实用量。一条失败不影响另一条；成功候选可以采用，失败不会自动付费重试。正在执行的组可通过组 ID 读取，两条已保存结果在刷新后仍存在。原请求编号保存在当前标签页，断线后先核对原请求；同编号只取回原组，不重新调用模型。

默认只预览选中的一个候选；用户可主动开启并排高级比较，也可切换桌面/390px 手机宽度。预览复用现有安全文档策略，使用 `sandbox="allow-scripts allow-forms"`，不授予同源、顶层导航和弹窗；CSP 的 `form-action 'none'` 保留，以支持阻止默认提交的表单事件，同时禁止真实网络提交。源码作为文本展示。

Worker 意外终止或存储不可用时，未确认完成的候选显示“结果待核对”，不会假称成功，也不自动重新调用。原 HTML 未保存成功时无法保证恢复该次输出；已有成功候选与原应用不受影响。单访客最多保留二十组，当前不提供自动清理或永久删除。

## 采用与冲突

候选在采用前不新增应用版本、不修改原应用当前指针。采用原应用时，在事务中再次检查组与候选归属、基准仍为当前版本、没有有效生成锁、版本未达 60 上限及目标项目仍有效。采用新应用还检查 100 个应用容量。成功后新增一个不可变版本，再更新当前指针与该候选的采用收据。

若原应用已被修改/还原、目标项目归档、生成锁或容量发生变化，整个采用失败，候选继续保留，不覆写新成果。用户可以核对后明确“另存私有应用”，此操作保留原应用并新建私有副本；仍校验归属、目标、锁与容量。每候选只采用一次，同种采用重试返回原收据，不重复版本。另一个未采用候选仍可查看或另存；已采用候选需要再复制时可使用现有应用历史复制功能。

## 接口与数据

- `GET /api/candidates`：当前访客最近二十组的元数据，不返回所有 HTML。
- `GET /api/candidates/:id`：当前访客的一组和两个候选详情。
- `POST /api/candidates`：`{requestId,prompt,mode,model?,appId?,baseVersionId?,managedProjectId?,confirmTwoCalls:true}`。已有应用需匹配当前基准；新应用可指定目标项目。用户不能自定义数量、策略或任意模型。
- `POST /api/candidates/:id/adopt`：`{candidateId,asNew?}`。默认采用至原应用；无原应用时创建新应用，`asNew:true` 明确另存。首次成功 201，已采用同种结果重试 200。

所有写入校验本站 Origin 和会话；跨访客组、源应用及跨工作空间目标拒绝访问。schema-only `0007_generation_candidates.sql` 新增组与候选表、索引及外键，不改写旧数据。子请求继续使用现有 `forma_requests`，model 用量的 operation 为 candidate，预算不按模型或策略重置。

## 验证边界

真实 SQLite 与 fetch mock 覆盖两份预算原子拒绝、同组并发幂等、最后两份额度竞争、部分模型/保存失败、候选不覆盖原作、采用幂等及基准/锁/容量变化、原子回滚、刷新读取、无 Key 示例，以及 iframe 属性和 CSP 契约。全程零真实模型调用。本批不启动额外常驻预览，也不部署；浏览器交互与线上验证待整合后单独记录。
