# 先讨论，再构建

工作台明确区分“构建应用”和“先讨论”。构建沿用既有代码生成流程；讨论只返回文字，不创建代码版本、不改变当前预览、不执行回答中的 HTML 或代码。构建模式下遇到疑似普通问题时，本地规则提示用户选择继续构建或带入讨论，不调用额外分类模型。

讨论回答可“采用为构建需求”：先打开可编辑内容，有原构建草稿时明确选择追加或替换。长回答只提供标注过的节选。填入后仍需用户明确发送构建请求。无模型配置时不能生成讨论回答，但草稿可保留，也可切回示例构建。

## 上下文与草稿

- 已有应用使用独立讨论线程，文字对话与代码版本按时间合并展示。每次讨论记录其保存代码版本；只读取经过归属检查的持久 HTML，不读取 iframe 内的临时表单、任务或计时数据。
- 构建前可以保留多个独立讨论，按当前项目分组选择。明确采用后首次生成新应用，再将所采用的构建前线程关联到新应用；关联只改线程元数据，不改代码或历史。冲突时原讨论保留。
- 构建草稿按服务器返回的 workspace ID 及应用/构建前上下文保存；讨论草稿按同一 workspace 及线程保存。切换和刷新不把不同应用、线程或匿名身份混在一起。首次生成后，用户正在起草的下一条构建需求转移到新应用；旧异步结果不回写当前输入。
- 浏览器存储使用空间 ID 作命名空间，不保存 Cookie 或 Key。清除 Cookie 后是新身份，不能看到旧匿名身份的草稿。旧版无命名空间 outbox 只迁移服务端确认属于当前访客的请求。构建前其他未发送草稿可在首页恢复选择中找到。

草稿在本地浏览器，讨论记录在 D1。浏览器存储被禁用时构建输入退回本页内存，并显示当前无法持久保存。没有正式账号、跨设备同步或匿名身份找回能力。

## 讨论 API

所有操作通过匿名 HttpOnly Cookie 检查工作空间归属，写请求检查 Origin，拒绝未知字段。

- `GET /api/discussions?appId=&managedProjectId=&threadId=`：读取线程及轮次。应用和构建前项目范围互斥；返回当前拥有的 workspace ID、线程列表、选中线程、轮次及限制。
- `POST /api/discussions/threads`：提供 UUID `threadId` 和可选应用/项目范围，幂等建立元数据。每空间最多 50 个构建前线程，每应用一个独立线程。
- `POST /api/discussions`：`threadId`、UUID `requestId`、1–4000 字 `prompt`，可选 `baseVersionId`、实际白名单 `model`。每线程最多 100 轮，最近六轮且最多 12000 字作为文字上下文。
- `GET /api/discussions/requests/:id`：只返回当前访客讨论的 running / done / failed / expired 状态及线程快照，不复用 HTML 生成任务 DTO。
- `POST /api/discussions/threads/:id/attach`：提供新应用 `appId`，仅将当前拥有且未关联的构建前线程关联到自己的应用。已有独立线程或仍在处理时拒绝，不删除对话。

回复为纯文本，最多 1600 输出 token、8000 字符、2 分钟等待；不完整输出视为失败。显示消息立即入列、清空已发送输入，处理期间仍可起草下一条，失败保留问题并提供核对后重试或编辑。恢复仅执行有限 GET 核对，当前 POST 进行中不重复查询/回调，等待不明确时不会自动再次调用模型。

## 费用、一致性与迁移

讨论复用 `forma_requests` 的 `mode=model`，`project_id=discussion:<threadId>`，usage operation 为 discuss。因此与生成、修改和两组候选共享访客每日 10 次、全站每日 50 次模型预算，UTC 计日，已开始的失败尝试也占额。返回实际 nullable token、模型、耗时与状态，不伪造余额或把未知用量写成零。

讨论租约独立于应用生成锁；每次只处理线程中的一个请求。预算、usage 与原始问题在一个事务登记，完成写入受请求状态、租约与归属栅栏保护。完成请求重试不重复付费；确认失败/过期后仅用户主动重试才分配新编号。停止客户端核对或离开页面不保证取消已经开始的服务端调用或费用。

追加 schema-only `0008_text_discussions.sql`，接在稳定 0007 之后，新增线程与轮次表。旧迁移不变，无已有 HTML、版本或指针回填。通用 HTML 恢复接口排除 discussion: 与 candidate: 命名空间。

## 验证

`tests/discussions.test.mjs` 用真实 SQLite 与模拟 Responses 响应检查归属、文本保存、HTML 不改写、同一预算、幂等、失败和真实用量、过期 worker 栅栏、关联、上限和 schema 链。`tests/discussion-client.test.mjs` 检查空间/应用/构建前草稿隔离、身份变更与旧写入拒绝、迟到快照合并和恢复次数边界。

测试不发起真实模型调用。统一浏览器仍需验收模式选择、发送/下一草稿、刷新恢复、原稿追加/替换、线程与应用切换、采用关联，以及回答中的 HTML 始终只显示为文字。预览继续保留 allow-scripts allow-forms、form-action none、无同源与外部网络能力。
